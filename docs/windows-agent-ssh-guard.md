# Windows agent SSH 进程保护

`rdog-ssh-guard` 是供 Windows OpenSSH 强制命令调用的独立程序. 它读取 OpenSSH 提供的 `SSH_ORIGINAL_COMMAND`, 以 Windows 系统目录中的 `cmd.exe` 执行原命令. 它继承标准输入输出和退出码, 不缓存命令输出. 没有原命令时拒绝执行.

程序在恢复子进程之前将其加入带 `KILL_ON_JOB_CLOSE` 的 Windows Job. 它持有当前 SSH 会话的 `sshd` 进程句柄; 会话结束、guard 退出或 guard 崩溃时, Job 关闭并终止其中的进程. 原命令正常退出时也会关闭 Job, 因此此入口不适合需要在命令结束后继续运行的后台任务.

该程序需要在专用 agent 密钥上配置强制命令. 人工密钥、SFTP 和其他现有 SSH 入口不应共用这项强制命令. 专用密钥本身的 SFTP 和无命令交互 shell 不受支持; 没有执行命令的端口转发不经过 guard. Windows OpenSSH 使用自定义默认 shell 的环境尚未验证. 只有实际切换到专用密钥且无法绕过这一入口的 agent 命令才受保护; 添加程序或密钥本身不能强制已有 agent 调用迁移.

断网后清理取决于 SSH 检测到会话失效的时间. 进程通过服务、计划任务或 WMI 等方式独立创建时不保证属于 Job. 该机制没有内存上限, 也不会修正命令本身的内存增长.

2026-11-02 在独立 Windows OpenSSH 实例中, 临时专用密钥和授权文件经过测试. 正常标准输入、标准错误、非零退出码、SSH 客户端终止、客户端暂停后的 keepalive 清理和 guard 崩溃清理均通过单次验证; 两条独立受管会话的进程互不影响. 原身份的 SFTP 和独立测试隧道经过复测. 测试资源已清理, 原 SSH 服务未修改. 真机验证后仅补充了 Job 绑定失败时的错误检查, 最终源码通过 Windows 目标编译检查, 未重复真机测试. Job 绑定失败的故障注入、自定义 shell 和真实网络黑洞尚未验证.
