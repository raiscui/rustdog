# RAI-417 文件传输残骸: `@file-cancel` + 空闲 TTL sweep + `@file-list`

> 结论: 已落地并推 PR (**已推待合**). 未合并, 合并由 Captain 决定.

## 1. 结论

被拒绝或中途中断的传输此前会永久留下两样东西: 盘上的 `.yino-partial`, 与 `TRANSFERS` 里一条
进程生命周期内不回收的 `HashMap` 条目. 对被门禁拒绝的传输尤其致命 —— **拒绝本该是零副作用**,
一次被拒的 178 MB 上传就是 178 MB 垃圾.

三处一起收口: 主动取消、空闲过期、同 id 换路径重开. 三者共用同一条 `reap_partial` 回收路径,
避免将来某一条漏掉.

| `src/shell/tests.rs` | mock executor 的穷举匹配补两个新臂 (不加则编译不过) |

**为什么是后台线程而不是惰性扫描**: 残留的正是**没有后续请求**的场景 —— 传输失败或被拒之后
daemon 安静下来. 惰性扫描只能保证"有人再来时会被清", 保证不了"盘上没有残留".

**为什么加 `@file-list`**: 验收要求"注册表无残留"能被证明. 没有它, 唯一的回读手段是"再取消一次
看它回 `absent`" —— 那只证明幂等, 不证明表里干净. 输出按 `transfer_id` 排序, `HashMap` 的迭代
顺序不能进证据.

## 2.5 评审把范围推到了"暂存区结构" (值得单列)

评审连着四轮都落在同一处: 暂存名 = 目标名 + `.yino-partial` 后缀, 于是暂存文件长在**目标的命名空间**
里, "某个目标名恰好是别人的暂存名"的拼法可以无限枚举 —— 先后被指出大小写变体、Win32 结尾的点/空格、
NTFS 备用数据流 (`x.yino-partial:s`)、8.3 短名. 每封一条就冒出下一条.

到第四轮我判定**问题在前提, 不在规则**, 改成**保留目录**:

- 暂存文件一律放 `<目标目录>/.rdog-partial/`, 文件名 = 截断目标名 + 目标串哈希 (SHA-256 前 16 位) + `.partial`
  (推导的唯一定义在 `staging_path()`);
- 目标路径不得包含 `.rdog-partial` 这个目录组件 (拒绝并说明原因).

单射性由"目录+文件名相同 ⇒ 目标相同"给出, 命名空间隔离由"目录不同"给出 —— 两条都不再引用任何平台
别名规则. 目录组件比较仍按平台归一 (去结尾点空格、Windows 上剥 ADS、折叠大小写), 但它退为第二道,
不再是隔离本体.

代价与边界都写在规格里: 两个目标若被文件系统视为**同一目的地** (例如 Windows 上 `x.bin` 与
`x.bin.`), 各自有暂存文件与各自的 sha256 校验, 两次提交对同一目的地 rename 是"两个写者对同一路径"
的正常语义, 不是任一次传输的数据损坏; 要彻底避免需要给目的地加锁, 本票不做.

**教训**: 局部修补会让相邻条款继续互相打脸. 一条规则如果必须靠"再补一条平台特例"才能守住, 该检查的
是这条规则的**作用域前提**, 而不是继续补.

## 3. 一个必须写下来的分叉点

今天三种中止 (显式取消 / 摘要不符 / open 拒绝) **都是终态的**, 所以"一律删半成品"成立.

但 RAI-367 的"中途路径丢失"是**可续传**中止: 续传 offset 的真相源就是半成品的文件长度
(`execute_put_file` 的 resume 分支). 那时删了, `resume:true` 会静默从 0 重传 —— 而回执看起来
完全正常. 这比"续传不了"更坏, 因为它伪装成成功.

已在 `reap_idle_transfers` 的注释里指回规格 §2.5, 并在 D1 证据项加了"续传起始 offset 不等于 0".
本次**不**预先加 `resumable` 字段: 今天没有代码产生这种中止, 加了就是没人消费的死字段.

## 4. 验证

`cargo test --bin rdog`: **1114 passed / 0 failed / 2 ignored** (基线 1107 + 新增 7).

| 用例 | 断言 |
| --- | --- |
| `cancel_drops_registry_entry_and_partial` | 盘上无残留 + `@file-list` 无该 id + 二次取消回 `absent` |
| `cancel_leaves_existing_target_file_untouched` | 取消上传不删目标路径上原有文件 |
| `cancel_of_download_session_drops_entry_without_touching_source` | 下载会话取消不删源文件 |
| `idle_reap_reclaims_stale_session_and_keeps_progressing_one` | 同一次调用里只收过期那条, 在推进的不受影响 |
| `reopening_same_id_on_another_path_reclaims_the_old_partial` | 旧半成品被回收, 进度不继承 (`written=0`) |
| `file_cancel_and_file_list_should_parse_from_line_protocol` | 两个 verb 能从**行协议**到达 |
| `should_reject_zero_file_transfer_recovery_limits` | 两项配置为 0 都被拒 |

时间相关用例用 `#[cfg(test)] stamp_last_activity_for_tests` 写死时刻, 不靠 sleep; 读表的用例
共享模块顶层唯一一把 `TRANSFER_TABLE_TEST_LOCK`, 而且只断言自己的 id, 不断言整表条数 ——
同进程并行跑的其他用例随时在表里放东西, 整表计数必然 flaky.
