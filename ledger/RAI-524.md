# RAI-524 — TLS link 的读写任务可同时进入同一 rustls Connection

> 票: RAI-524。关联: RAI-464 (归因拆分), RAI-564 (残余的客户端 session 缺陷)。

### 2026-11-26 RAI-524: 病根证实 + 互斥修法落地

`zenoh-link-tls` 1.8.0/1.10.2 的 `LinkUnicastTls` 用 `UnsafeCell<TlsStream>` + **两把不同**的锁
(`read_mtx` / `write_mtx`) + `unsafe impl Sync`, 读写任务可同时对同一 rustls `Connection` 取 `&mut`。
判别探针 (只读原子计数, 不加锁): **失败写 15/15 都伴随并发读在场, 成功写的对照比例 42%**
(15 次全落 42% 一侧, 偶然概率 3e-6); 指纹 = daemon 侧 `write #4` + `handshake not complete`。

修法: 读写共用一把锁, 两侧都改「锁内非阻塞 poll + 锁外自持 waker 等待」, `close()` 锁内只做非阻塞
flush/shutdown。
- 对照 A (两把锁 + 读短临界区): 8/8 轮红 —— 窗口变短无用;
- 对照 B (单锁 + 阻塞读): 20/20 失败、2s→121s —— 会饿死写;
- 本修法: **1200 次连接里 `handshake not complete` 0 次**, 吞吐 90ms/次 (基线约 100ms/次)。

残余失败 (约 1/400) 是 RAI-564 的指纹 (daemon 无错误行 + client session 提前关闭), 不同源。
