# RAI-510 — 上限语义只落在直接被 kill 的那一层

> 票: RAI-510。合并: PR `capy/rai510-timeout-scope`。

### 2026-11-26 RAI-510: 超时整组回收 + job 级预算 + compile-only 也设上限

- 提交: 待合入后补 (标题: `fix(ci): 超时整组回收 + job 级预算 + compile-only 也设上限 (RAI-510)`)

三条同源缺陷, 都是「上限只落在直接被 kill 的那一层」:

1. **超时留孤儿 (最坏)**: `subprocess.run(timeout=…)` 只终止直接子进程, `cargo test` 派生的
   测试二进制与 daemon 变成孤儿留在 runner 上, 污染同 job 后续 target —— 今天 `control_websocket`
   挂死把 `restored_index_*` 拖下水就是这条。改成子进程进独立进程组 (POSIX
   `start_new_session` + `killpg`, windows `taskkill /F /T /PID`), 超时后整组回收。
2. **每 target 1500s 不是 job 级预算**: 两次挂起就把 60 分钟 job 撑爆。新增
   `JOB_BUDGET_SECONDS` (默认 3300s, env 可覆盖) 与 `BUDGET_FLOOR_SECONDS`, 每个 target 的实际
   上限 = min(单 target 上限, 剩余预算); 预算耗尽时**判红并点名未执行的 target**, 不是静默跳过。
3. **compile-only 的 `--no-run` 没有上限**: 同样会挂 (链接/依赖解析), 同样无名字。现在共用上面
   两个上限。

验证 (判据是进程回读, 不是「代码里加了 kill」):

- 旧做法负对照: `subprocess.run(timeout=2)` 跑「bash 派生 python 睡 300s」→ 超时返回后
  `pgrep -af <marker>` 仍有 **1 个存活** (孤儿子进程)。
- 新做法: 同一命令 `run(timeout=2)` → `exit 124`, 日志 `已整组终止 (killpg <pgid>)`,
  `pgrep` 存活 **0**。
- 预算: `RDOG_JOB_BUDGET_SECONDS=1` 跑 `--os windows-latest` → `job 预算 1s 不足, 未执行:
  computer_use_density` 并判红 (同时触发「零执行」守卫)。

**已知边界 (写下来而不是假装没有)**: 子进程若自己 `setsid`/双重 fork 逃出进程组, `killpg` 抓不到
它。rdog 自己的 daemon 不这么做; 真遇到时按 `docs/solutions/logic-errors/gnu-coreutils-kill-neg-pid-argument-ambiguity.md`
那套「按 PID 回读确认」的方式再补。

### 2026-11-26 RAI-510 评审 F1–F7 (七条全是同一形状: 修的东西自己漏了一处同形的洞)

- 提交: 待合入后补 (标题: `fix(ci): 评审 F1–F7 — 无条件整组回收 + job 真实剩余预算 (RAI-510)`)

**F1 (high) `_kill_tree` 先看 `proc.poll()`**: 直接子进程先退出就 `return "already exited"`,
后代继续活着 —— 那正是孤儿的定义。评审用本函数实测: 形状 A(中间退出、孙进程同组握管道)
存活后代 1, 形状 B(中间活着) 0。同处 `os.getpgid()` 在 leader 已回收时抛 `ProcessLookupError`
也被当成「组没了」。修: spawn 时固定 `pgid = pid`, 无条件 `killpg`, 只有 `ProcessLookupError`
当「组确实没了」, 并**回读** `/proc` 里该 pgid 的存活成员 (排除僵尸)。

**F2 (high) windows 上要杀的对象在树外**: `rdog daemon` 默认重开成 `hidden-daemon --child`
(`CREATE_NO_WINDOW|DETACHED_PROCESS`), `taskkill /T` 够不着。修: 跑 target 时统一注入
`RDOG_DAEMON_FOREGROUND=1`; `taskkill` 返回码非 0 时把 stderr 写进日志并判失败。

**F3 (high) 预算与 job 真实剩余时间无关**: 3300s 是「本步开始 + 常数」, 而 job 60 分钟、前缀
(checkout/cargo-prep/unit tests) 实测 ubuntu 88–103s / macos 149–167s / windows 203–239s, 依赖一改
还会更久 → 必然越过 3600 被 cancel。修: job 第一个 step 写 `$RUNNER_TEMP/job-started-at`, 脚本按
`job_timeout − elapsed − 180s 余量` 算 deadline。

**F4** 超时后 `communicate(timeout=30)` 拿不到输出时, 原写法把已收到的证据整段丢弃 → 现在把
`TimeoutExpired.output` 拼回 partial。**F5** 预算耗尽与「零执行」同时判红、且 `return 1` 早于写
summary → 零执行守卫在预算已报时让位, summary 先写后判。**F6** 剩余不足按预算口径 skip, 不再给
「121s 截短上限」(会把慢而健康的 target 记成挂死); 截短提示只在真的截短时出现。**F7** 文档比代码
承诺得多 → 现在**真的回读** (POSIX 读 `/proc`; windows 明确写「无回读, 只看返回码」)。

验证 (形状 A 与 B 都跑了):

| 形状 | 旧实现 | 新实现 |
| --- | --- | --- |
| A 中间进程先退出、孙进程同组 | `already exited` → 存活 1 | `killpg …, 回读 0 存活` → 存活 0 |
| B 中间进程活着 | `killpg` → 存活 0 | `killpg …, 回读 0 存活` → 存活 0 |

预算派生: job 起点 3500s 前 + 60min → `剩余 -90s` → 判红并点名; 120min → `剩余 3519s` → 正常跑。

### 2026-11-26 RAI-510 复评: F4 弄崩了、F3 没闭合 (第二次「负对照绕开失效分支」)

- 提交: 待合入后补 (标题: `fix(ci): F4 字节解码 + F3 起点前置与 fail-closed (RAI-510)`)

**F4 (最重)**: `str + bytes` 抛 TypeError。`TimeoutExpired.output` 即使在 `text=True` 下也是
**bytes** (CPython `_check_timeout` 里是 `b"".join(...)`), 于是只要 target **超时前打印过任何东西**
(现实中总是), 异常穿出 `main()`, **summary 一个字节都不写** —— 我为「不丢证据」改的那一行, 恰好
在有证据时把整个 summary 打没了。修: 统一 `_as_text()` 逐段解码后再拼。**负对照补上「有输出的
超时」这一形状** (我原来的形状都无输出, `expired.output is None`, 正好绕过这一行)。

**F3 三条**:
1. 起点 step 原本排在 `Checkout` + `cargo-prep` **之后**, 恰好把要修的前缀排除在 elapsed 之外 →
   挪到每个 test job 的**第一个 step**;
2. `RDOG_JOB_TIMEOUT_MINUTES: "60"` 抄了三遍 → 改成与 `timeout-minutes` **共用一个 YAML anchor**
   (`x-job-timeout-minutes`), 6 个 job 与 3 处预算 env 都引用它;
3. 起点文件缺失/空/垃圾时静默退回固定预算 → 现在 CI 上**判红**并点名该查哪个文件 (本地才允许退回)。

**F4 另外半条**: 超时后读管道尾巴的 30s 也计入预算 (`deadline -= extra_wait`), 不再只靠 180s 余量兜。

验证:

| 形状 | 结果 |
| --- | --- |
| 超时前有输出 (`echo PARTIAL-EVIDENCE-LINE; sleep 300`, timeout=1) | 不抛异常, 证据行保留, `exit 124`, `回读 0 存活` |
| 起点文件缺失 + `GITHUB_ACTIONS=true` | `exit 1`, `job 起点缺失或不可解析 (No such file…)` |
| 起点文件是 `garbage` | `exit 1`, 同上并回显内容 |
| 本地无起点 (非 CI) | 退回 `本步固定预算 3300s` 并正常执行 |

### 2026-11-26 顺带: GitHub Actions 不接受自定义顶层键

- 提交: 待合入后补 (标题: `ci: anchor 改挂在 job 上 (GitHub 不接受自定义顶层键)`)

为了「timeout-minutes 与预算 env 共用一个值」我把 YAML anchor 放在文件头自定义键
`x-job-timeout-minutes` 上 —— **GitHub Actions 只接受已知顶层键, 整份 workflow 被判非法**,
run 直接 failure 且没有 job。锚点改挂在第一个 job 的 `timeout-minutes` 上, 其余 job 与预算 env
引用同一个 `*job-timeout-minutes`。教训与今天那条倡议一致: **「省一个字面量」的改动也要先看用得上的
那个解析器认不认**。

### 2026-11-26 RAI-510 二轮复核: 三件「报告会撒谎」的问题

- 提交: 待合入后补 (标题: `fix(ci): 超时输出不再重复拼接 + summary 点名未执行的 target + 载体 anchor 名 (RAI-510)`)

**必改 1 (最重) 超时日志重复拼接**: 超时后再调 `communicate()` 返回的是**从启动起累积的全量**,
已经包含 `expired.output`; 再拼一次让每行出现两遍 → `summarize()` 把 `test result:` 数两遍,
超时 target 在 summary 里的 `passed/failed/ignored` 变**真实值的 2 倍**。实测 `mark_count: 2` →
修饰后 `1`。顺带补上 `except` 分支丢掉的 stderr。

**必改 2 summary 不点名**: 预算耗尽时判红、注解也点名了, 但 **summary 正文里 `grep` 不到那个 target**
(executed 表空、只剩 exempt 表) —— 读 summary 的人看不出是谁没跑。现在 summary 单列
「**not executed — job 预算不足**」表, 逐条点名并注明不计入 ran。

**必改 3 载体写着已被删掉的非法 anchor 名**: `ci-merge-gate.md` 还写着 `x-job-timeout-minutes`
(就是会让 workflow 判非法的自定义顶层键)。改成 `&job-timeout-minutes` (定义在 `ci.yml` 第一个
job 的 `timeout-minutes` 上) 并把「为什么不能放文件头」写在同一句里 —— **踩过的坑恰好是文档唯一
记下的地方, 记错了等于没记**。

**中危 文案诚实度**: 回读只声明「**组内**」存活 (`组内回读 0 存活`); §3b 补两条边界:
POSIX 上 `setsid` 逃出组的后代打不到 (实测: 日志 `组内回读 0 存活`, 实际存活 1, `extra_wait`
30.03 说明尾巴那支真走过); windows 上 leader 先死时 `taskkill /T /PID <dead pid>` 只报 not found,
后代不回收 —— 那是「诚实判红、孤儿仍在」, 不是「杀干净」。

**low**: `knowledge-carriers` 与三个 build job 上多余的 Record 步骤删掉 (只有 test job 的
integration 步骤读它); 文件头多余空行清掉。
