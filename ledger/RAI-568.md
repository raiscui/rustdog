# RAI-568 — 并行测试不再重复分配测试端口

### 2026-11-27 RAI-568: 收敛 `next_free_port()` 的 TCP 端口分配

- 提交: bfdce40

13 处集成测试实现与 `src/daemon.rs` 的测试实现统一为 `tests/support/test_ports.rs`。
在每个测试进程里，先原子认领唯一端口再探测可用性；PID 只用于错开进程的起点，不承诺跨进程保留端口。

旧 helper 的负对照：Linux 同时运行原版 `control_lanes` 和 `control_pty`，提高 libtest 并发后，
`control_lanes` 第 16 轮在原报错点复现 `AddrInUse`。独立的并行认领回归对旧 helper 连红三轮；
其中第 2 轮的 worker 0 和 2 在任何调用方 bind 前拿到同一个端口。

### 2026-11-27 RAI-568: 记录端口认领的边界

- 提交: 47b2e6a

`tests/support/test_ports.rs` 的 bind 探测不保留 socket。调用方重绑前，
外部进程（包括另一个 test binary）仍可能抢占；PID 步长只分散起点，不分配独占区段。
单进程已尝试的候选（含被占用的）不回收；耗尽时以 `test TCP port range exhausted`
报告 PID 和容量。根路径下的 `src/daemon.rs` 在 `#[cfg(all(test, unix))]`
模块用 `#[path = "../tests/support/test_ports.rs"]` 引入同一实现；
Linux 上 `cargo test --bin rdog daemon::tests::daemon_workers` 实际执行 3/3。
