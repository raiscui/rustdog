# RAI-579 账本

`zenoh_router_client` 的 multi one-shot 家族偶发「非零退出 + stdout 全空」。本票本地复现率
**0/20**（`--test-threads=16`，当前 main），改走「结构事实 + 可确定性验证的那一半」。

## 2026-11-27 多行 one-shot 失败不再静默 + helper 有真实预算

- 提交: 待合入后补 (标题: `fix(control): 多行 one-shot 失败点名第几条与帧数 + helper 不再无界等待 (RAI-579)`)

### F2: helper 的 `timeout` 从来不是预算

`run_control_multi_one_shot` 原来用 `Command::output()` —— **没有超时也没有 kill**，`timeout`
只当「未找到目标 service」的重试截止时刻用。客户端一旦挂住（daemon 卡死/应答不到），用例就无限
等到 job 级超时，日志只剩 `has been running for over N seconds`。

- 修: 每次尝试 `spawn` + `try_wait` 轮询，预算到点 `kill`，并在 stderr 追加
  `<control 超时被杀>` —— 失败由此自证是「客户端被预算杀了」而不是「daemon 回了空结果」。
- 负对照 `multi_one_shot_helper_must_not_hang_past_its_budget`: `kill -STOP` 冻住 daemon
  （TCP 仍可连、应答永远不到），2s 预算下必须收手并点名；改前同一形状 >20s 不返回。

### F1 第一步: 超时/失败时把「跑到哪了」变成可读事实

`send_control_lines_collect_frames` 原来把失败折叠成一个 `Err`，帧只在成功时打印 ——
一次超时就是**非零退出 + stdout 全空**，读的人分不清「一条都没发出去」与「跑了一半才断」。

- 修: 返回 `ControlLinesOutcome { line_frames, failure }`；`failure` 带
  `line_index / total_lines / dispatched_any / cause`。调用方**先打印已完成的帧**，再把失败
  报成 `Err`（退出码仍非零），文案由纯函数 `multi_one_shot_failure_message` 生成。
- 单测两条钉住文案：`multi_one_shot_failure_message_must_name_the_line_and_frame_count`
  （第 2 条 / 共 3 条 / 已完成 1 行 / 不盲目重跑）与
  `multi_one_shot_failure_message_must_not_claim_frames_when_nothing_was_sent`
  （没发出任何一条时不许说「第 1 条失败」）。
- 端到端**改为人工一次性取证**, 不留慢用例: 目标不存在时 CLI 实测 (exit 1, stdout 空):

  ```
  error: 多行 one-shot 失败于第 1 条 (共 2 条, 已完成 0 条, 已收到 0 帧):
  Zenoh autodiscovery 在 3000ms 内未找到可连接的 router locator. 已完成的响应已打到 stdout; ...
  ```

  原本想把它固化成集成用例, 但它依赖 discovery 耗时: macOS 上 3s 重试窗口内客户端还没开口
  就被预算杀掉, 只剩 `<control 超时被杀>`; 把窗口抬到 20s+20s 收尾就是一个 40s 的用例。
  所以只保留纯单测, 集成形状不进仓。
- helper 顺带修掉一个诊断缺陷: 重试窗口用尽时最后一跳只剩窗口残留, 客户端会先被预算杀掉、
  它自己那句「第几条失败」说不出口。现在窗口用尽后补一次 20s 收尾尝试。

### 端到端读数 (由复核补上)

「中途超时后已收到的帧打到 stdout」原先标未验 —— 本机的 line-control 响应等待有 **60s 地板**
（`client_pty.rs:30` 的 `60s.max(timeout)`，与 transport 无关，见 RAI-592），本地造不出 3s 超时。
复核用 TCP entry-point 补上了读数：`FIRST_FRAME` + `sleep 75` ⇒ **exit 1 @60.06s、stdout 有已完成
的帧、stderr「第 2 条 / 共 2 条 / 已收到 1 帧」**。这条现在是已验证。

### F1 第二步: 不补重试

多行 one-shot 是整段脚本，超时后整段重放可能让前半段的副作用执行两次。是否可重放要能区分
「请求没送达」与「已执行但应答丢了」——做不到就不加重试。本票不加。
