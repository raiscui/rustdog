# RAI-711 账本

从 RAI-705 拆出的**同 ID 幂等自动续传**。RAI-705 只留观测 (`bulk_chunk_ack_unanswered` + daemon 的
`iroh bulk ack …`), 自动重拨整段摘掉 —— 只读评审在初版判定 1 severe: 丢失成功的 `@file-end` 回执后
重开, daemon 没有"已提交结果"可回放, 第二次提交会把成品替换掉。

## 2026-11-28 先定验收面: 对账以盘上事实为主判据, 总 deadline 120 s

- 提交: 64153a2

验收矩阵 (九格四列: 输入 / 期望终态 / 失败判据 / 需要的原始行) 落在
`specs/rdog-bulk-idempotent-resume-plan.md`, 并同步进票面描述。本提交只含验收面, 不含 `src/` 改动。

两条已定口径 (Captain 2026-11-28):

1. **对账主判据是盘上的成品事实**: 目标存在 + 大小等于源 + sha256 等于源 ⇒ 返回原终态 (`committed`),
   不重传、不替换; 内存表只作快速路径, 不得是唯一判据; 盘上不匹配且无记录 ⇒ **结果未知**, 不重传。
   该判据天然跨重启 (所以"跨重启回放"不必另开票), 代价是只在重放路径上的一次哈希。**假阳性**
   (成品本来就在、内容恰好相同) 按成功返回是对的 —— 终态不可区分; 文档写明它不证明"本次写入发生"。
2. **总 deadline 120 s (初值), 路径与 ack 重拨共享同一条**: 不是各自记账, 不是逐项相加。到期错误必须
   写清耗尽的是哪条预算、最后观测状态 (路径类别 / `written` / 最后一条 daemon 行时间戳) 与"结果未知"
   措辞。若真机上把正常慢链路 (20 MiB @ ~83 kB/s) 判死, 带数据回来调, 不偷改成无限。

M0 (证据关联) 的字段已批: daemon 入站行与 ack 行带 `transfer_id` + `attempt` + `offset`, 客户端错误
文本同组字段, 字段名与出现位置写进契约文档 —— 三件不能按"时间接近"猜关联, 否则该格判失败。

## 2026-11-28 M4 结构化错误 + M2 ID 预分配

- 提交: 85b516f

### M4: 重放决策读来源, 不读文案

- `src/control_iroh.rs`: `LaneError { kind: LaneFailure, message }`,
  `LaneFailure = AckUnansweredLive | AckUnansweredClosed | PeerClosed | Local`。读回执超时的时候先读
  `close_reason()`: 连接仍开 ⇒ `AckUnansweredLive` (对端可能已执行), 已关 ⇒ `AckUnansweredClosed`。
- `src/transfer_cli.rs`: `ExchangeError` 带 `FailureKind`, 失败来源记进 `BulkPathRecorder.failure`,
  重拨决策是纯函数 `retry_step(&failure, waited)` —— **只看 `kind`**。`AckUnansweredLive` 与
  `PathRefused` 都**不在**重试集里 (前者是对端可能已提交, 后者换个时刻也不该放行)。
- 稳定码映射读**结构化字段**: `failure_code()` 认 `error_code`, 也认门禁拒绝那种把码放在 `error`
  里的信封 (`{"code":65,"error":"iroh_path_unknown"}`), 匹配用**全等**不用子串。

**回归(已修, 有单测钉住)**: 第一版只读 `error_code`, 于是门禁拒绝被归类成 `Local`, "路径读不出 ⇒
重拨"静默失效 —— `a_put_killed_mid_upload_resumes_on_the_first_retry` 本地稳定红 (exit=1)。
`a_gate_refusal_envelope_is_classified_by_its_code_not_by_prose` 现在把两种信封各自钉死。

**扫点计数**: 生产代码里按文案匹配错误的 **0 处** (原有唯一一处在 `run_iroh_bulk`, 已换成 kind);
剩下的 `err.contains(...)` 全在测试断言里 (断言用户可见文案)。

## 2026-11-28 M1 盘上对账 (重放路径专用) + #204 三处 low finding 的处置

- 提交: b28e4a1 (M1), b498b50 (M1b 混合版本), 801b17a (M1b TCP 对齐), 0d0c 账本

- `@put-file` 可选字段 `verify_committed:true`: 客户端只在 store 里还留着 id (上一次没干净收尾) 时带,
  正常首传不多一次哈希。
- daemon: 内存 `COMMITTED` 快速路径 → 盘上目标 (存在 + 大小 + sha256) 三层判定; 相等 ⇒
  `committed/replayed:true` (客户端搬 0 字节, 回执标 `replayed=committed`); 存在但不符 ⇒
  `file_transfer_replay_mismatch` (已登记稳定码总表, 不覆盖不重传); **不存在 ⇒ 正常 open**
  (提交必然留下目标文件, 所以"没有目标"是"没提交过"的正面证据)。
- 假阳性语义写在 `replay_state` 的注释里: 目标本来就在且内容相同也判已提交, 终态不可区分是对的,
  但不证明本次写入发生过。
- 用例: `replay_state_reads_the_disk_when_the_memory_record_is_gone` (跨重启)、
  `replay_state_memory_record_is_only_a_fast_path`、**负对照** `replay_state_never_calls_a_mismatched_target_committed`
  (同大小不同内容 / 大小不符都必须是 Mismatch, 且盘上字节不动)、`replay_state_treats_a_missing_target_as_never_committed`、
  端到端 `a_committed_target_makes_the_replay_move_no_bytes` (一个 `@file-chunk` 都不发、盘上字节不变)。

### 哈希成本实测 (同机, 20 MiB / 200 MiB)

| 文件 | `sha256sum` | `openssl dgst -sha256` |
| --- | --- | --- |
| 20 MiB | 0.02 s | 0.02 s |
| 200 MiB | 0.15 s | 0.18 s |

**口径**: 这两个工具走 SHA-NI; 仓库里 `sha2 = "0.10.9"` 默认是纯软件实现, 真数字要在 M6 的真 lane
replay 上取 —— 这里给的是同机同文件的下界, 不当"可接受"的结论。

### M1b 混合版本: 旧 daemon 会静默忽略新字段 ⇒ 客户端 fail closed

- `@put-file` 的回执现在带 `"reconcile": "disk"` (做过盘上对账的标记); 客户端带 `verify_committed`
  时若回执里没有这个标记, 必须报 `file_transfer_reconcile_unsupported` 并取消刚开的会话 —— 旧 daemon
  按 `serde_json::Value` 解析载荷, **未知字段不报错**, 静默忽略会把"结果未知"变成"直接重传"。
- 用例: `a_peer_that_ignores_the_reconcile_request_fails_closed`。
- `Absent` 分支的前提写进代码注释与矩阵: 依赖两次尝试之间没有外部删除/移动目标。
- TCP 与 iroh 同一条规则: 判断写在共享驱动 `run_put_inner`, 两条 lane 都带 `verify_committed`、都按
  `reconcile` 标记 fail closed; `--restart` 不拦 (语义就是显式同意替换)。中断重跑的 TCP 用户会第一次
  看到"要么升级对端, 要么显式 --restart" —— 这是有意为之: 不留静默窗口。

## 2026-11-28 M1 severe 2: 缓存不作判据之后的发布语义

- 提交: d9671c4 (severe 1: 删掉 COMMITTED 缓存), 8d01eed (提交守卫), 5c24031 (原子 no-replace 发布)

  (拒 + 别人字节不动 + 临时文件清掉) 与 `a_normal_upload_still_overwrites_an_existing_target`。
- **severe 2 第二段**: 重放会话的发布改走 `publish_no_replace` —— Linux `renameat2(RENAME_NOREPLACE)`、
