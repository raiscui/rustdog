# RAI-594 账本

`orphaned_partial_is_reclaimed_by_the_resume_window` 在 macOS CI 上挡住纯文档 PR (#191),
断言 `reaped == 0` 收到 2。不是 flake, 是测试隔离缺陷。

## 2026-11-27 断言从「全局聚合」改成「自己的对象」

- 提交: 0c31eda

### 机制: `reaped` 是全局聚合, 假时钟又越过了真实时刻

`reap_idle_transfers` 一轮扫遍**会话表**与**孤儿表**, 返回的 `reaped` 是「本轮全局回收了几条」。
会话表和孤儿表都是进程级单例, 并行用例按真实时刻登记的条目会一起被数进来; 一条外来上传
就够贡献 2 (会话 +1, 同轮转出的孤儿再 +1) ⇒ 本用例的 `reaped` 变成 2。

方向相反的另一半同样成立: 用例把锚点设在 `now_ms() + 1_000_000`, 于是这一轮 sweep 会把
**别人**按真实时刻登记的会话与孤儿全判成过期 (`now - last_activity ≈ 1e6`), 既污染计数又
删掉别人的状态。原来的「锁内快照 + 清空 + 还原」只护住了孤儿表, 护不住会话表, 而且快照与
插入是两次独立加锁, 中间能塞进别人的条目。

### 修法

- 断言只盯**本用例自己的键与文件**: 窗口内 → 文件在 + 自己的键在; 窗口后 → 文件没了 +
  自己的键没了。`reaped` 只进断言消息当读数, 不再是断言对象。
- 两轮 sweep 的时钟取**真实时钟之前** (`now_ms() - 20_000` 起, 窗口 10s): 按真实时刻登记的
  条目对它们 `now - last_activity` 恒为 0。这条把概率压低了, 但**没有从构造上消掉**这条路易:
  偏移够大时, 登记时间早于截止线的外来条目仍会被扫掉 —— 评审 medium 1, 由 `b5d3b52` 换成
  小数值假时钟, 见下一节。(本节记 `0c31eda` 当时代码的实际形态, 不复写后续修法。)
- 去掉快照 / `mem::take` / 还原: 不再需要独占整表, 也就不再丢并行用例的条目。

另在同一条 solution 里补了第 5 例 (`docs/solutions/best-practices/
parallel-test-global-state-single-lock.md`): 锁只串行化, 挡不住「返回值是全局聚合」;
假时钟不许越过真实时刻。

### 验证

- **复现 (旧实现, 确定性)**: 临时用例按真实时刻登记一条外来会话, 再原样复刻旧断言 ⇒
  红在 `left: 2, right: 0`, 与 macOS CI 的 panic 文本一致。
- **负对照**: ① 回收删文件但不删键 ⇒ 红在「孤儿条目必须从表里消失」(`reaped=1`);
  ② 回收无视窗口 ⇒ 红在「孤儿在窗口内必须留着可续」(`reaped=1`)。两条都证明断言盯着
  自己的对象, 不是盯着聚合值。
- **并行全量**: `cargo test --bin rdog` (默认并发) 连续 20 轮, 0 红 (1314 passed / 4 ignored 每轮)。
- **macOS**: 本机是 linux, 跑不到 macOS-latest; 以 CI 读数补, 见 PR 描述。
- 守卫: `check-carrier-assertions.py` OK; `check-bookkeeping.py` 见本条。

## 2026-11-27 评审跟进: 小数值假时钟

- 提交: b5d3b52

合入版本 (#194 / `61ba308`) 把锚点取成 `now_ms() - 20_000`。它挡住了原用例的失败形态,
但「真实时钟 + 偏移」只把概率降低, 没把路消掉: 偏移够大时, 登记时间早于截止线的并行用例
条目 (例如换 id 换目标那条用例按旧会话活动时间登记的孤儿) 仍会被这一轮 sweep 连键带文件
删掉。评审 medium 1 指的就是这条。

修法: 换成本模块已有的**小数值假时钟** (`restored_index_lets_the_sweep_reclaim_after_restart`
同款)。按真实 epoch ms 登记的会话与孤儿对 `1_000 / 10_999 / 11_001` 的 `now - last_activity`
恒为 0, 于是**本用例的 sweep** 从构造上删不到别人的状态, 而不是"偏移足够小所以大概率扫不到"。
这是**单向**保护: 反方向 (别人的真实时钟 sweep 回收本用例的 `1_000`) 靠的仍是
`SWEEP_TEST_LOCK` —— 测试内的 sweep 都持它, 单元测试进程里也不起生产 worker。
换句话说, 隔离靠的是"锁 + 时钟各管一个方向", 不是单靠时间戳。

同批两处评审意见:

- **low**: 第一轮采样点原来卡在 idle 阈值上 (年龄 1_000, `idle_timeout_ms` 也是 1_000) ——
  孤儿误按 `age > idle_timeout_ms` 回收的实现(第一轮保留、第二轮删除)也能让四条断言全过。
  改成 `窗口 - 1`, 年龄 9_999 远越空闲阈值仍落在窗口内。这条锁的是**阈值替换**
  (按空闲阈值回收), **不**锁窗口判据的等号: 两侧采样各距窗口边界 1 ms, `>=` 写成 `>` 仍全过。
- **medium 2 (文档口径)**: `reaped == 2` 不需要两类外来条目 —— 一条外来上传就贡献 2
  (会话 +1, 同轮转出的孤儿再 +1)。见上文机制段的措辞更正。

负对照 (均为临时改动跑过, 事后已还原):

| 临时改动 | 红在哪 |
|---|---|
| 回收删文件但不删键 | 「窗口过了, 孤儿条目必须从表里消失 (reaped=1)」 |
| 回收无视窗口 | 「孤儿在窗口内必须留着可续 (reaped=1)」 |
| 回收改按空闲阈值 (严格 `>`) | 同窗口内断言 —— 正是老采样会放过的形状 |

并行读数 (绑 `b5d3b52`): `cargo test --bin rdog` 默认并发 20 轮 0 红。
