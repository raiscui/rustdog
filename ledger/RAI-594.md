# RAI-594 账本

`orphaned_partial_is_reclaimed_by_the_resume_window` 在 macOS CI 上挡住纯文档 PR (#191),
断言 `reaped == 0` 收到 2。不是 flake, 是测试隔离缺陷。

## 2026-11-27 断言从「全局聚合」改成「自己的对象」

- 提交: 0c31eda

### 机制: `reaped` 是全局聚合, 假时钟又越过了真实时刻

`reap_idle_transfers` 一轮扫遍**会话表**与**孤儿表**, 返回的 `reaped` 是「本轮全局回收了几条」。
会话表和孤儿表都是进程级单例, 并行用例按真实时刻登记的条目会一起被数进来 ⇒ 本用例的
`reaped` 变成 2。

方向相反的另一半同样成立: 用例把锚点设在 `now_ms() + 1_000_000`, 于是这一轮 sweep 会把
**别人**按真实时刻登记的会话与孤儿全判成过期 (`now - last_activity ≈ 1e6`), 既污染计数又
删掉别人的状态。原来的「锁内快照 + 清空 + 还原」只护住了孤儿表, 护不住会话表, 而且快照与
插入是两次独立加锁, 中间能塞进别人的条目。

### 修法

- 断言只盯**本用例自己的键与文件**: 窗口内 → 文件在 + 自己的键在; 窗口后 → 文件没了 +
  自己的键没了。`reaped` 只进断言消息当读数, 不再是断言对象。
- 两轮 sweep 的时钟都压在**真实时刻之前** (`now - 20_000` 起, 窗口 10s), 别人的
  `now - last_activity` 恒为 0, 谁也扫不到谁。
- 去掉快照 / `mem::take` / 还原: 不再需要独占整表, 也就不再丢并行用例的条目。

另在同一条 solution 里补了第 5 例 (`docs/solutions/best-practices/
parallel-test-global-state-single-lock.md`): 锁只串行化, 挡不住「返回值是全局聚合」;
假时钟不许越过真实时刻。

### 验证

- **复现 (旧实现, 确定性)**: 临时用例按真实时刻登记一条外来会话, 再原样复刻旧断言 ⇒
  红在 `left: 2, right: 0`, 与 macOS CI 的 panic 文本一致。
- **负对照**: ① 回收删文件但不删键 ⇒ 红在「孤儿条目必须从表里消失」(`reaped=1`);
  ② 回收无视窗口 ⇒ 红在「孤儿在窗口内必须留着可续」(`reaped=1`)。两条都证明断言盯着
  自己的对象, 不是盯着聚合值。
- **并行全量**: `cargo test --bin rdog` (默认并发) 连续 20 轮, 0 红 (1314 passed / 4 ignored 每轮)。
- **macOS**: 本机是 linux, 跑不到 macOS-latest; 以 CI 读数补, 见 PR 描述。
- 守卫: `check-carrier-assertions.py` OK; `check-bookkeeping.py` 见本条。
