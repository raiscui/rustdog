# RAI-582 账本

`zenoh_router_client` 里两处「把内核/收集器不保证的事写成了断言」。两条同属 e2e 读侧契约,
合一个 PR。

## 2026-11-27 PTY 控制帧不强交替 + marker 可能落在 1024 字节块边界

- 提交: 待合入后补 (标题: `fix(test): PTY 控制帧不再假定与输出帧交替 + sentinel 等整行 (RAI-582)`)

### 机制 1: PTY 控制帧与输出帧没有严格交替的保证

`control_should_detach_and_attach_pty_in_zenoh_profile` 红在 `:1887`:
`unexpected closed payload: @pty-output {…,"data":"DQo="}`, `DQo=` 就是 `\r\n` ——
`@pty-close` 与 `@pty-closed` 之间插进了一条子进程输出的换行帧。PTY 输出切在哪个 chunk
由内核与调度决定, 用例却断言「下一条一定是 `@pty-closed`」。

- 修: `wait_for_pty_control_frame` —— 等控制帧时跳过 `@pty-output`; 异型帧仍然立刻失败,
  并把 daemon 日志与跳过计数打出来。
- **没放宽断言**: close 仍要求 `@pty-closed` 且带 `force_close`, 跳过的只是子进程输出帧。
- 读数: 修前当前树 `--test-threads=2` **1/20 红**; 修后 **20 轮 0 红**。
- 排除的竞争解释 (都是实测, 不是推断): 端口撞号 —— 只把分配换回旧 `bind(0)` 形状 20 轮
  **0 红**; 时序窗口 —— detach→attach 往返实测 **2.8ms**, 而 `SECOND` 在 open 后 1s 才出现,
  余量 350 倍。

### 机制 2: marker 命中不等于整行到齐

`daemon_should_reuse_same_control_key_after_restart_by_default` 红在 `:2034`
(`first output should contain control_key`, 1/20)。合流收集器按 1024 字节块追加,
`wait_until_output_contains` 只在 `contains(marker)` 上返回 ⇒ 读同一行后半段
`control_key=` 的调用方拿到半行。

- 修: 判据改成「marker 之后还出现了换行」(`marker_line_complete`)。
- 负对照 `sentinel_wait_must_wait_for_the_whole_line`: 造一个 marker 落在 1024 字节边界的
  快照, 旧判据判「到了」而 `parse_control_key` 返回 `None` (正是那条 panic); 补齐整行后
  读到 `rdog/lab/stable`。**这条负对照是确定性的, 不靠复现率。**

载体: `docs/solutions/conventions/daemon-log-sentinel-e2e-contract.md` 新增 2c, 并点明它与
2a 同源 —— 都是「sentinel 说的状态比实际状态多」: 2a 是顺序先于对象, 2c 是位置先于内容。
