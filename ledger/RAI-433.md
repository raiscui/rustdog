单文件账本让任意两张 PR 都在 `WORKLOG.md` 尾部追加 —— rebase 必在同一处冲突, 而 rebase 又会
重写所有 sha, 于是「冲突」和「记账」互相放大 (RAI-411 一天吃掉四轮 CI 就是这条链)。改动:

1. **存储按票分**: 新票写 `ledger/<票号>.md`; `WORKLOG.md` 退化为索引 + 2026-11-26 之前归档。
   RAI-411 的 11 段条目已迁到 `ledger/RAI-411.md` 作为第一个样板。
2. **时序补丁**: PR 内条目写「票号 + 提交标题」, `- 提交: <sha>` 在**合入后**由纯账本提交补齐
   (纯账本提交本来就豁免)。不变量没动, 只把写 sha 的时点挪到 sha 稳定之后。
3. **守卫分两档**: `--report-only` 用于 `pull_request` (只发 `::warning::`); 新增 `--main
   --main-grace N` (默认 3) 用于 `push` 到 main —— 最新 3 个 commit 记宽限, 更早的仍缺 sha 即
   退出码 1。**同一次改动里 CI 的两个步骤按事件分开**, 不再只在 push 时 report-only。
4. **顺带补合并门缺口**: 「基座不是 main 的 PR 检查不能当合并依据」写成 `ci-merge-gate.md`
   §3c 的硬判定 (改基到 main 重跑 / 层间绿只判本层 / rebase 后重跑), 并记下实测代价:
   `mergeable=dirty` 时 GitHub 生成不出 merge commit, 新 head 的 `pull_request` 运行一条都没有。

守卫自测 (临时仓, 不依赖真仓库状态):

- 4 个未记账的工作 commit + `--main --main-grace 3` → 最新 3 个记宽限并打印, 更早的 2 个判红,
  退出码 1;
- 把 4 个 sha 写进 `ledger/RAI-433.md` 再提交一个纯账本提交 → 退出码 0, 纯账本提交被豁免。

**补一条设计缺陷 (评审前自查发现)**: 原来的范围是「最新一个已被引用 commit 之后」, 于是一个
漏账 commit 只要后面有一个 commit 被记账, 它就永远落在基线之外 —— 再也不会被判红。`--main`
改成按窗口 (最近 `--limit` 个) 扫描, 漏账只能靠被推出窗口逃掉, 那是有界且写明了的代价。
临时仓实测: `work A`(漏账) 后面跟一个已记账的 `work B` —— 旧逻辑漏掉, 新逻辑判红。

### 2026-11-26 RAI-433 评审 H1/M1/M2

- 提交: 17924e2

**H1 (high, 门禁在 main 上看不到任何东西)**: `commit_shas` 带 `--first-parent`, 而 main 上落的是
`Merge pull request #N` —— PR 的工作 commit 在 merge commit 的**第二父线**上, 永远走不到; 叠加基线
截断后范围常只剩那个 merge commit, 而它恰好落进「只改账本」豁免。于是**任何 PR 都能完全不写账本
绿灯合入**, 代价不是延迟发现而是永不发现。修: `--main` 关掉 `--first-parent` 且 `--no-merges`
(merge 本身不承载工作), PR 侧 checkout 取 `pull_request.head.sha` 并用 `--since origin/<base>`。
复现与验证在临时仓: 造一个没进账本的 PR 分支 `--no-ff` 合进 main, 修饰前范围恒为 1 个 merge
commit; 修饰后该工作 commit 可见, 被推出宽限后退出码 1。

**H2 (评审的第二条 high)**: 基线截断让漏账 commit 在被任何更新的 commit 记账后永久消失 ——
上一轮已改成窗口扫描, 这一条在 `547e337` 已生效。

**M1 (宽限只在 push 时跑)**: 安静的 main (周末/冻结) 永远等不到判红。新增
`.github/workflows/ledger-audit.yml` (每日 03:00 + 手动), 只跑守卫本身, 不跑 build/test, 也不产生
PR 检查, 所以不影响必需检查表。help 文案同步改成「范围内最新 N 个工作 commit」。

**M2 (占位按标题全局认领)**: 一条 `fix: typo` 这类通用占位能吞掉同标题的任意多个 commit。改成
标题在范围内必须唯一, 命中多个时按「占位标题不唯一」判红 (临时仓实测两个同标题 commit 都被点名)。
